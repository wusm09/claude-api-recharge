## 充值之前，先弄懂钱是怎么扣的

Claude API 采用预充值模式：先往账户里充一笔钱，之后每次调用按实际消耗的 token 数扣费，输入和输出分开计价，不同模型单价不同。绝大多数组织都是这种预付费方式，按月出账单只对少数企业客户开放。

几个直接影响充值决策的基本事实：

- **没有长期免费层。** Anthropic 不提供持续免费的 API 额度，新注册账号有时会拿到一笔小额的一次性赠送信用，用完即止。
- **订阅和 API 互不相通。** claude.ai 的聊天额度不能拿来调 API，反过来也一样。
- **调用上限跟着消费走。** 新账号默认处于低速率层级，添加支付方式并完成首次额度购买后，会进入付费层级，每分钟请求数和 token 吞吐上限都会提高。很多人第一次正式测试就撞上 429 报错，原因多半就是跳过了 Billing 设置这一步。

换句话说，充值不只是“让 API 能用”，也直接决定你的调用规模上限。

## 官方充值完整流程

官方渠道的入口是 Claude Console，也就是 Anthropic 的开发者后台，搜索 "Anthropic Console" 即可找到。流程五步：

1. **注册账号并创建组织。** 用邮箱注册后验证邮箱，然后建立一个组织——这是所有 API 用量的计费单位。公司项目建议在组织内单开工作区，把测试和生产环境的密钥、账单分开管理。
2. **在 Billing 里添加支付方式。** 这里需要一张可用于国际支付的信用卡，或直接购买预付信用。完成首次额度购买后，账号才会进入付费层级。
3. **购买预充值额度。** 选一个金额充值，用多少扣多少。
4. **设置消费上限。** 这一步别省。API 按 token 扣费，一个写坏的循环脚本几小时就能烧出一张意外账单；设了上限，最坏结果是报错停机，而不是月底看账单发懵。
5. **创建 API 密钥。** 在设置的 API Keys 里新建，密钥以 sk-ant- 开头，**只在创建时显示一次**，离开页面就再也看不到，务必当场保存。别把密钥写死在代码里，放进环境变量：

bash
export ANTHROPIC_API_KEY="sk-ant-..."


第一次调用时把 max_tokens 设小一点（比如 128），用一条短消息验证密钥和余额都正常，再开始正式接入。max_tokens 只是输出上限，不会预扣等额费用。

官方渠道的前提很明确：你得有一张能完成国际支付的卡。如果这一步就走不通，直接跳到下面的替代方案。

## 官方充值常见报错对照

| 报错 | 含义 | 处理方式 |
| --- | --- | --- |
| 401 | 密钥无效 | 检查密钥是否复制完整、环境变量是否生效 |
| 400 balance-too-low | 余额不足 | 回 Console 继续充值 |
| 402 | 计费错误 | 检查 Billing 设置和支付方式 |
| 429 | 触发速率限制 | 稍等重试；长期触发说明该升级消费层级了 |
| 529 | API 过载 | 服务端问题，退避重试即可 |

4xx 类错误重试没有意义，先把账号或请求本身的问题解决掉。官方 SDK 会自动对 429 和 5xx 做退避重试，自己手写 HTTP 调用的话，记得实现指数退避。

## 充值之后：四个让钱花得慢一点的习惯

**分层选模型。** 简单的分类、抽取任务交给 Haiku 4.5（$1/$5），日常开发用 Sonnet 5.5，只在推理质量真正影响结果时才上 Opus。生产环境常见的做法是路由：先用便宜模型判断请求复杂度，复杂的再转给贵的。

**批处理打五折。** 不需要实时返回的任务（批量摘要、数据标注）走 Batch API，输入输出都按标准价的 50% 计费，24 小时内出结果，实际通常快得多。

**用好提示词缓存。** 把固定的长系统提示、文档、工具定义标记为可缓存内容，重复请求读取缓存时，输入成本约为原价的 0.1 倍。写入缓存有 1.25 倍（5 分钟档）或 2 倍（1 小时档）的加价，但只要命中一两次就能回本。注意缓存按前缀匹配，系统提示里插一个时间戳，后面的缓存就全部失效了。

**从第一天就记录 usage。** 每次响应里的 usage 对象包含输入、输出和缓存 token 的精确数字，把它写进日志，成本结构心里有数，比等月账单来了再倒推强得多。

## 常见问题

**订阅了 Claude Pro，还需要给 API 充值吗？**
需要。两者是完全独立的计费体系，Pro 的聊天额度不能用于 API。

**有免费额度吗？**
没有长期免费层。新账号偶尔有一次性小额赠送，能否拿到、金额多少，以注册时的实际情况为准。

**充值后怎么确认到账和消耗？**
Console 里可以查看余额和当前限额；每次 API 响应的 usage 字段记录该次调用的具体 token 消耗。

**余额用完 API 会立刻停吗？**
余额不足时会返回 400/402 类计费错误，调用被拒绝，续充后恢复。这也是消费上限的价值：把“意外账单”变成“可控的停机”。

**密钥泄露了怎么办？**
立刻回 Console 删除旧密钥并新建一个。密钥一旦出现在公开仓库，自动扫描工具通常几小时内就能找到，产生的消耗由账户承担——这也是为什么强调用环境变量而不是硬编码。
